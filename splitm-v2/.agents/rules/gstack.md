# Rule: gstack Engineering Discipline & Workflow

## Core Directives
1. **Always apply the 7-phase sprint mindset:**
   - **Think** (`office-hours`): Challenge premises, interrogate problem statements with forcing questions.
   - **Plan** (`ceo-review` & `eng-review`): Expand vision to 10-star UX, lock architecture and invariants.
   - **Build**: Implement complete features, edge cases, and tests. Reject shortcuts.
   - **Review** (`review`): Hunt for production-killing bugs, race conditions, and floating-point errors.
   - **Test** (`qa`): Real behavioral validation across edge inputs and edge cases.
   - **Ship** (`ship`): Verify test suites, validate docs, clean commits.
   - **Reflect** (`retro`): Track trends and improve velocity.

2. **Code Quality & Slop Prevention:**
   - Avoid generic, bloated boilerplate.
   - Ensure rich aesthetics, smooth micro-interactions, responsive typography, and curated color palettes.
   - Reject unverified assumptions in financial math.

3. **User Primacy:**
   - Clarify high-level choices using interactive questions.
   - Never override architectural direction without explicit sign-off.
