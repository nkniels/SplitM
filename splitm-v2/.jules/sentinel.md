## 2024-05-18 - [Fix Firestore Rules Missing Authz & Null Ref]
**Vulnerability:** IDOR in Firestore rules. Subcollections and root collections (`members`, `expenses`, `settlements`) were allowing any authenticated user to write or delete documents. Also, combining `read`/`write` rules while checking `request.resource.data` led to null reference errors during `read` or `delete` because `request.resource` is only available during writes.
**Learning:** Always check ownership (e.g., `isGroupOwner`) for write operations. Never evaluate `request.resource.data` on a rule that allows `read` or `delete`.
**Prevention:** Separate `read`/`delete` from `create`/`update` rules. Validate ownership via `groupId` for subcollections and root collections.
## 2024-10-24 - Firestore Rules IDOR and `resource == null` Auth Bypass
**Vulnerability:** Several Firestore rules contained `resource == null` checks within shared `write` rules (bypassing ownership verification on creation, allowing unauthorized creations like arbitrary users, backups, or notifications). Also, updates on root collections (members, expenses, settlements, groups) only checked `resource.data` (the existing document) and not `request.resource.data` (the incoming data), allowing an Insecure Direct Object Reference (IDOR) where users could modify the `groupId` or `createdBy` field to transfer ownership to another group or user.
**Learning:** `resource` is null during document creation, which evaluates to true and bypasses ownership checks if mixed into a generic `write` rule. When evaluating Firestore update rules, checking only `resource.data` does not protect against malicious incoming data that modifies restricted fields.
**Prevention:** Separate `read`/`delete` operations from `create`/`update` operations. Never use `resource == null` in shared write rules; always validate ownership during creation using `request.resource.data`. For updates, validate both `resource.data` (to ensure the user has permission to modify the document) and `request.resource.data` (to ensure they aren't transferring ownership or modifying restricted references).
